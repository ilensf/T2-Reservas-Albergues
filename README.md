## Estrutura do repositorio

Mantede sempre esta estructura:

```text
p1-albergues/
├── app.py            (aplicación principal)
├── compose.yaml
├── .env.example
├── requirements.txt
├── README.md
└── src/              todo o resto do código
    ├── __init__.py
    ├── xera_datos.py
    └── copia.sh
```

- Na raíz só van a configuración, o README e o punto de entrada (`app.py`).
- Os scripts execútanse **desde a raíz**: `python -m src.xera_datos`, `python app.py …`, `./src/copia.sh`.

## Primeiros pasos

```bash
# 1. Levanta os servizos
docker compose up -d

# 2. Contorno virtual e dependencias
python -m venv .venv
.venv\Scripts\activate         # en Windows
pip install -r requirements.txt

# 3. Xera e carga datos de proba
python -m src.xera_datos --albergues 40 --peregrinos 1500 --reservas 5000 --semente 42

# 4. Póe en marcha a aplicación
python app.py
```

## Servizos (`compose.yaml`)

Levanta PostgreSQL 17, Redis 7.4 (con AOF), MongoDB 8.0 e Adminer. Cada un con volume nomeado, rede propia e healthcheck. As credenciais van en `.env` (non se sube ao repositorio).

## Decisiones tomadas

**Redis**
- Clave `dispo:<albergue_id>:<YYYY-MM-DD>` → prazas libres dun albergue nunha noite.
- Clave `cache:<camino>:<YYYY-MM-DD>` → caché con TTL de 60 segundos para albergues dun camiño con prazas libres.
- `reservar()` usa `DECRBY` atómico. Se non hai praza ou falla PostgreSQL, revén o contador co `INCRBY`.

**PostgreSQL**
- O `id` de `reservas` é `GENERATED BY DEFAULT AS IDENTITY` para insertar reservas novas sen pasarle `id` a man.

**Fichas MongoDB**
- Campos base (`albergue_id`, `nome`, `camino`, `servizos`, `horario`) e campos variables por albergue (`contacto`, `admite_cans`, `bicicletas`, `idiomas`, `opinions`, `titularidade`).

## Proba de sobreventa

`app.py` lanza 20 reservas simultáneas sobre un albergue con 3 prazas. Resultado: exactamente 3 aceptadas, sen sobreventa.

## Medicións

Consulta de dispoñibilidade (100 repeticións): PostgreSQL ~22 ms, Redis ~0,4 ms. Redis é moito máis rápido.

## Copias (`src/copia.sh`)

Fai `pg_dump` de PostgreSQL e `mongodump` de MongoDB en `copias/copia_<data>_<hora>/`.

```bash
./src/copia.sh
```

## Orde recomendada

1. `compose.yaml` con PostgreSQL, Redis e MongoDB.
2. `xera_datos.py` para xerar e cargar datos.
3. `app.py` con contadores, `reservar()`, caché, proba de sobreventa e medicións.
4. `src/copia.sh` e proba de restauración.

Facede un *commit* ao rematar cada paso.
